Flujo completo Geosupport - Carga de imagenes PAO

Documento maestro del flujo por etapas: preparacion de paths, carga al datastore y mosaico, actualizacion de footprints, normalizacion Rasterio y preparacion del APRX para publicacion.

01Paths datastore 02Carga mosaico 03Footprints indice 04Normalizacion 05APRX publicacion

Vision General

El flujo compila el procesamiento de una entrega de imagenes drone PAO desde la carpeta de entrada hasta la preparacion del APRX para publicacion. Cada etapa deja outputs propios y puede validarse antes de avanzar.

Principio operativo Las imagenes de entrada se consideran confiables como entrega nueva. El flujo valida nombre, sector, destino y estados de carga.
Fuente de nombre final La fecha viene del nombre o de json/fechas.json; el sector viene del cruce espacial.
Control de escritura Las etapas que escriben en datastore, GDB, mosaico o APRX parten con parametros de revision antes de modificar originales.

Orden de ejecucion

  1. Ejecutar etapa 1 y validar 04_ready_for_datastore.csv.
  2. Ejecutar etapa 2 con DRY_RUN = True; luego False para cargar.
  3. Ejecutar etapa 3 para anexar footprints al indice y recalcular Nombre_de_Vuelo.
  4. Ejecutar etapa 4 para normalizar imagenes con Rasterio y revisar salidas.
  5. Ejecutar etapa 5 para preparar el APRX y guardar copia de revision.
01

Preparar paths destino para datastore

Recibe la carpeta de imagenes nuevas, detecta imagenes TIF/TIFF, calcula el sector por cruce espacial y genera el nombre final y la ruta destino en el datastore.

ElementoDetalle
Notebook01_preparar_paths_datastore.ipynb
Documento detallado01_preparar_paths_datastore.html
Entrada principalPATH_INPUT_IMAGENES, PATH_FC_INDICE_VUELOS_IMGS, json/fechas.json
Output claveoutputs/etapa_01_preparar_paths_datastore/04_ready_for_datastore.csv

Logica clave

  • Busqueda recursiva desde la carpeta input.
  • El nombre destino se crea con fecha + sector espacial: CL_MLP_PAO_IF_Ortho_YY_MM_DD_Sector.tif.
  • La fecha puede venir del nombre original o de una tabla/diccionario controlado en json/fechas.json.
  • El sector no se toma del nombre del archivo; viene del cruce espacial con el feature class de sectores.
  • El cruce espacial usa primero la query principal: Sensor <> 'DJI MATRICE 350 RTK'.
  • Las imagenes que no cruzan con la query principal se vuelven a cruzar contra el sensor excluido: Sensor = 'DJI MATRICE 350 RTK'.
  • El origen del cruce queda auditado en spatial_query_source.
  • Nombre final: CL_MLP_PAO_IF_Ortho_YY_MM_DD_Sector.tif.
  • Destino: raiz datastore + carpeta por sector + carpeta mensual + nombre final.
  • Exporta diagnostico de no cruzados como CSV y feature class de extents en GDB.
El archivo que alimenta la etapa 2 es 04_ready_for_datastore.csv. Los registros en 05_review_required.csv no deben avanzar hasta resolver fecha, sector o carpeta destino.
02

Cargar datastore y mosaic dataset

Copia las imagenes al datastore, las agrega al mosaic dataset, construye footprints y actualiza campos criticos.

ElementoDetalle
Notebook02_cargar_datastore_mosaico.ipynb
Documento detallado02_cargar_datastore_mosaico.html
Entrada principal04_ready_for_datastore.csv
Output claveoutputs/etapa_02_carga_datastore_mosaico/02_load_results.csv

Campos criticos actualizados

  • MaxPS = 10000, LowPS = 0.15, MinPS = 0.
  • Sector, FechaAdqui/Fecha_Adqui, URL, Proyecto, Sensor, FechaCarga/Fecha_Publ.
  • ProductName o ProductNam toma el OBJECTID del registro del mosaico.
Ejecutar primero con DRY_RUN = True. Cambiar a False solo cuando los paths y atributos esten validados.
03

Actualizar footprints en indice de vuelos

Exporta las geometrías de las imagenes cargadas desde el mosaic dataset, las adapta al esquema del indice de vuelos y recalcula Nombre_de_Vuelo.

ElementoDetalle
Notebook03_actualizar_footprints_indice.ipynb
Documento detallado03_actualizar_footprints_indice.html
Entrada principal02_load_results.csv, mosaic dataset, feature class indice.
Output claveoutputs/etapa_03_actualizar_footprints_indice/00_summary.csv

Operaciones

  • ExportMosaicDatasetGeometry para nombres cargados.
  • Renombre de campos: FechaAdqui -> Fecha_Adqu, FechaCarga -> Fecha_Publ, NombreVuelo -> Nombre_de_Vuelo, ProductName -> ProductNam.
  • Append al indice de vuelos.
  • Recalculo de Nombre_de_Vuelo con formato NNN_yy_mm_dd_sector, ordenado por Name ASC.
04

Normalizar imagenes con Rasterio

Genera versiones normalizadas de las imagenes usando el footprint como mascara, con salida RGB/alpha compatible para ArcGIS.

ElementoDetalle
Notebook04_normalizar_imagenes_rasterio.ipynb
Documento detallado04_normalizar_imagenes_rasterio.html
Entrada principal02_load_results.csv y feature class de footprints.
Output claveoutputs/etapa_04_normalizar_imagenes_rasterio/01_normalizacion_rasterio_resultados.csv

Normalizacion

  • Usa rasterio.mask.mask con crop=True.
  • Conserva RGB o convierte colormap de 1 banda a RGB.
  • Agrega banda alpha para transparencia limpia fuera del footprint.
  • Por defecto no reemplaza originales: REPLACE_ORIGINALS = False.
Validar los TIF normalizados en normalized_tif antes de activar reemplazo de originales.
05

Preparar APRX para publicacion

Agrega las imagenes cargadas como capas raster directas en el APRX, dentro del grupo de imagenes drone, y deja el proyecto listo para revision/publicacion.

ElementoDetalle
Notebook05_preparar_aprx_publicacion.ipynb
Documento detallado05_preparar_aprx_publicacion.html
Entrada principal02_load_results.csv y APRX operativo.
Output claveoutputs/etapa_05_preparar_aprx_publicacion/01_aprx_update_results.csv

Reglas APRX

  • Grupo destino: Vuelos Drone PAO > Imagenes Drone.
  • Evita duplicados por equivalencias de nombre.
  • Renombra removiendo CL_MLP_PAO_IF_Ortho_ y .tif.
  • Ordena de mas nueva a mas vieja.
  • Guarda copia de revision con saveACopy por defecto.
Mantener SAVE_ORIGINAL_APRX = False hasta revisar la copia generada en ArcGIS Pro.
