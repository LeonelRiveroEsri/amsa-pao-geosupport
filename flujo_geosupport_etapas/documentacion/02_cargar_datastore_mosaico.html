02 - Cargar datastore y mosaic dataset

Informe funcional de la segunda etapa del flujo Geosupport. Esta etapa copia las imagenes al datastore, las agrega al mosaic dataset, construye footprints y actualiza los campos criticos.

Objetivo

Ejecutar la carga operativa de las imagenes que ya fueron preparadas en la etapa 1. La entrada principal es 04_ready_for_datastore.csv, donde cada registro ya tiene ruta origen, nombre oficial y ruta destino completa en el datastore.

Esta etapa si puede escribir archivos en el datastore y modificar el mosaic dataset. Por eso el notebook queda configurado con DRY_RUN = True por defecto. La carga real solo debe ejecutarse despues de revisar el manifest y cambiar DRY_RUN = False.

Entrada

Entrada Descripcion Uso
READY_FOR_DATASTORE_CSV CSV 04_ready_for_datastore.csv generado por la etapa 1. Define que imagenes se copiaran y cargaran.
PATH_MOSAIC_DATASET Mosaic dataset corporativo donde se agregan las imagenes. Destino de AddRastersToMosaicDataset, BuildFootprints y actualizacion de atributos.
destination_path Path destino de cada imagen en el datastore. Se usa para copiar el archivo y luego como input de carga al mosaico.
expected_name Nombre oficial sin extension. Se usa como valor del campo Name para buscar y actualizar el registro en el mosaico.

Secuencia del flujo

1. Leer manifest Se cargan los registros listos desde 04_ready_for_datastore.csv.
2. Copiar al datastore Se copia cada imagen desde path hacia destination_path.
3. Agregar al mosaico Se ejecuta AddRastersToMosaicDataset usando el archivo ya ubicado en el datastore.
4. Footprint y atributos Se construye el footprint y se actualizan campos criticos del registro cargado.

Copia al datastore

La copia usa la ruta original de la etapa 1 y la ruta destino calculada. La carpeta destino se crea si no existe. Si el archivo ya existe y OVERWRITE_COPY = False, la copia no reemplaza el archivo y el estado queda como already_exists.

Parametro Valor recomendado Interpretacion
DRY_RUN True para validar, False para ejecutar. Controla si la etapa escribe realmente o solo simula.
OVERWRITE_COPY False Evita reemplazar imagenes ya existentes en el datastore.
SKIP_EXISTING_MOSAIC_NAME True Evita agregar al mosaico un registro si ya existe el mismo Name.

Metodo Add Raster

La carga al mosaic dataset se realiza con arcpy.management.AddRastersToMosaicDataset. El raster que se agrega es el archivo copiado al datastore, no el archivo original de entrada.

Actualizacion de campos criticos

La actualizacion se hace con arcpy.da.UpdateCursor filtrando por Name. El flujo revisa que campos existen en el mosaic dataset y actualiza solo los disponibles. Los campos inexistentes quedan reportados como attribute_missing_fields.

Campo del mosaico Valor asignado Regla
MaxPS10000Valor fijo estandar del flujo.
LowPS0.15Valor fijo estandar del flujo.
MinPS0Valor fijo solicitado para esta carga.
Sectorspatial_sector_rawSector original del feature class, calculado en etapa 1 por cruce espacial.
FechaAdqui / Fecha_AdquiFecha ISO desde expected_date_tokenConvierte YY_MM_DD a YYYY-MM-DD.
URLURL ImageServer con ruta relativa del datastoreConstruida como referencia al archivo publicado en el servicio de imagen.
ProyectoPAOValor fijo del proyecto.
SensorDJI Mavic EnterpriseValor fijo para esta familia de imagenes.
FechaCarga / Fecha_PublFecha actual de ejecucionRegistra la fecha en que se publica/carga la imagen.
ProductName o ProductNamOBJECTID del registro en el mosaic datasetSe toma del registro encontrado por Name. Si el campo es texto, se guarda como texto; si es numerico, se guarda como numero.
La actualizacion del campo de producto ocurre despues de agregar el raster, porque el OBJECTID solo existe cuando el registro ya fue creado en el mosaic dataset.

Resultados de salida

La etapa escribe resultados en una carpeta fija. Cada ejecucion reemplaza los CSV previos para mantener un unico resultado vigente.

outputs\etapa_02_carga_datastore_mosaico

Criterio para avanzar

  1. Ejecutar primero con DRY_RUN = True y revisar 01_load_input_with_attributes.csv.
  2. Confirmar que Name, Path_Destino, Sector, Fecha_Adqui y URL estan correctos.
  3. Cambiar a DRY_RUN = False para ejecutar la carga real.
  4. Revisar 02_load_results.csv y confirmar overall_status = ok para las imagenes procesadas.
  5. Resolver cualquier registro en 03_errors_review.csv antes de pasar a etapas posteriores.
